## About

Computer science undergraduate based in Pune, interested in what happens underneath the abstractions: how a search algorithm prunes a game tree, how a query ends up doing too much work, how a packet moves through a network stack, how a kernel boots. I like software where correctness can be verified and performance can be measured.

## What I'm Into

<table width="100%">
  <tr>
    <td width="50%" valign="top">
      <b>Search and the cost of a decision</b><br/>
      Chess engines are the most honest playground I know for algorithms. Every pruning heuristic is a bet that you can safely skip work, and the results are quantifiable: node counts, Perft correctness, self-play outcomes.
    </td>
    <td width="50%" valign="top">
      <b>Building it once from scratch</b><br/>
      An OS, a packet sniffer, a chess engine. Writing the layer others take for granted is the fastest way I know to understand it, and it changes how I write code on top of it.
    </td>
  </tr>
  <tr>
    <td width="50%" valign="top">
      <b>Performance as a habit</b><br/>
      The most satisfying diff is the one that does the same thing with less: fewer queries, fewer round trips, fewer allocations. Measure first, then be able to say exactly what changed and by how much.
    </td>
    <td width="50%" valign="top">
      <b>Classical meets learned</b><br/>
      Neural evaluation inside a hand-tuned search, or embeddings behind a code search tool. I'm interested in the seams: what to learn, what to keep deterministic, and how to ship a model inside a real binary.
    </td>
  </tr>
  <tr>
    <td width="50%" valign="top">
      <b>Offense to understand defense</b><br/>
      HackTheBox and CTFs keep me honest about how systems actually fail. Reading a machine the way an attacker does makes me a more careful engineer.
    </td>
    <td width="50%" valign="top">
      <b>Competitive programming</b><br/>
      Precise problem solving under time pressure. It keeps data structures and complexity analysis reflexive rather than something I look up.
    </td>
  </tr>
</table>
